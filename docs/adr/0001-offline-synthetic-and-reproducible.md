# ADR 0001: Offline, seeded synthetic data and a reproducibility manifest

## Status
Accepted.

## Context
The project evaluates lead prioritization and record deduplication. Real CRM
data is private, cannot be redistributed, and would make results impossible for
a third party to reproduce. We also want the benchmark to run with no network,
no API keys, and no model downloads, so it is cheap to run in CI and byte-for-byte
reproducible on any machine.

## Decision
- All data is generated by `leadsift.generate` from a single integer seed using
  `numpy.random.default_rng`. No file or network input is ever read.
- Conversion labels and duplicate pairs are produced by the *same* generator, so
  ground truth is always available for evaluation.
- Every benchmark run computes a SHA-256 `dataset_checksum` over the generated
  content and records it in both `results.json` and `manifest.json`, alongside
  the Python version, platform, dependency version, and git SHA (falling back to
  `"n/a"` when git is unavailable). This lets anyone prove which data a number
  was measured on.

## Consequences
- Results are reproducible and verifiable, but they measure behaviour on a
  *synthetic* distribution. The README states this plainly under "Known gaps".
- The generator is a modelling artefact: if it is too easy, scores look
  unrealistically high. We deliberately inject noise and hard cases, and a test
  (`test_fuzzy_is_not_perfect`) fails if dedup ever reaches a near-perfect score.
